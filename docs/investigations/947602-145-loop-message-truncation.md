## Source and installed runtime differ

`aimux doctor versions` reported CLI and project services on `local-94d85381`,
build `1791190709000-e3bf2324c837`. No local asset was installed, no shared
runtime was restarted, and no prompt was injected into a live agent.

The brief's suggestion that loop pokes bypass normalization is stale:
`watcher_delivery.rs` already calls `normalize_submitted_prompt` in both current
source and `94d85381`. That normalization dates to `7568cdfe8`.

The relevant source changes missing from the installed build are:

- `9591b985b`: replace the sync and async character/chunk walks with a staged
  prompt, loaded once and pasted once.
- `e7bf5f2f0`: preserve linefeeds with `paste-buffer -r`.
- `8a41facc4`: share the staged executors and their byte/argv gates.

At the investigation baseline, `LoopWatcherTask` passes the entire `send.text`
to `deliver_agent_input_async`. Its direct async path contextualizes and
normalizes the text, then passes the whole composed prompt to the staged async
executor. There is no additional head-slicing operation in that source chain.
This inspection does not prove what the older installed process delivered.

## Verification scope

The existing `tmux::staged_prompt_tests::the_sync_and_async_executors_emit_the_same_argv`
gate now retains its long numbered-list case and also exercises a multiline
briefing generated by `build_overseer_briefing`, plus its contextualized,
normalized form. All cases exceed the former 4,000-byte chunk boundary.

For each case, both executors must stage exactly the original composed bytes,
not merely agree with each other. Success must use one load and one paste.
The existing load/paste failure and cleanup comparisons still apply.

At the investigation baseline, scoped runs passed all 14 staged-prompt tests,
the existing multiline input-route test, and six idle-fleet watcher tests.
Deliberately truncating loop prompts in
the shared staging writer failed the extended parity test even though both
executors staged the same truncated bytes. Removing `paste-buffer -r` failed
the existing single-load/paste argv test. Restoring pristine source passed all
14 staged tests after each mutation.

Item 146's async delivery-seam work subsequently merged as PR #467. Integrating
it retains the paste-time privacy assertions inside every new prompt/failure
case. All 13 staged tests on that merged source passed, as did
`production_delivery_executors_preserve_payload_and_failures`, which exercises
30 scenarios through concrete sync, bounded, and async delivery executors.
Verification logs are summarized with the PR.

These tests observe staged bytes and tmux command arguments. They do not
exercise a live Claude/Codex composer, prove receiver acceptance, or prove the
watcher's call-site wiring under mutation. No renderer test or production
delivery change was added to conceal that uncertainty.

Outcome: historical pre-rendering truncation is confirmed; no new current-source
failure has been established. The exact screenshot event and behavior of the
older installed agent runtime remain unverified. A passing source staging gate
must not be reported as an installed-runtime fix.
